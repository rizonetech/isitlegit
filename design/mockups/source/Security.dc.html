Security

How does IsItLegit stay safe while opening attackers' mail?

By treating every email, attachment, link and page as hostile. Untrusted content is only ever data, links are opened in a sealed browser that types made-up values, and code, not a model, decides who receives mail.

By Derick Payne, Rizonetech · Reviewed 26 Oct 2026

A sealed browser for links

Muse Wonder walks suspicious links inside a contained browser session. Our own driver enforces the limits: at most 8 steps and 60 seconds, no downloads, nothing but http and https.

Canary values only

When a fake login asks for a password, the walkthrough types values generated for that case alone. A real password never enters a form, and every action is logged.

Content stays data

Email and page text reach a model only inside marked untrusted blocks, after hidden text has been pulled out and logged as evidence against the sender.

No model picks a recipient

Replies go to the member who forwarded, alerts to a protected business's registered address. Addresses, subjects and links come from code; the model only fills checked fields.

A floor that cannot be talked down

A changed bank account or a password form on a lookalike domain fixes a minimum verdict. Text that tells an AI "this is safe" loses to that floor and becomes evidence itself.

Caps in code

Model spend has hard daily and total caps. When one is reached that model switches off for the day and your report is marked partial, so a flood of mail cannot run up a bill or a backlog.

How do we protect your data?

  • Each organisation sees only its own cases; a missing case and someone else's case look the same.
  • Report links are signed and expire after 7 days.
  • Raw mail and attachments are deleted after 30 days.
  • The admin console sits behind Cloudflare Access.
  • Tests prove that injected instructions do not change a verdict, a recipient or a tool call.

Found a vulnerability?

Tell us privately through GitHub's private vulnerability reporting. Only the maintainers see the report. Please do not open a public issue or test against the live service with real people's mail.

Report a vulnerability

First response within 3 working days. We confirm we have it and who is handling it.

In scope: the intake channels, prompt injection that changes a verdict or recipient, escape from the sealed browser, and access to another member's data.

Fixed issues are published as GitHub security advisories, with the credit you choose. Full policy in SECURITY.md.
