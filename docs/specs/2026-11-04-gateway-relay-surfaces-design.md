## Member settings

Extend the existing Domains detail card using its tokens and AppShell. An organisation administrator selects a verified domain and its discovered gateway/provider binding, reads the stored revision and state, and enters one public CIDR per line. A labelled help sentence explains that proposals are untrusted until independently verified. The form never fetches a tenant-supplied source URL. The server calls the checks-owned lifecycle API and enforces its schema, permissions, revision and idempotency rules; the UI never writes tables directly.

Save proposal and Edit create a pending immutable revision. Edit confirmation states that prior configured trust ends immediately. Revoke has an explicit confirmation and leaves a visible revoked hold. Restore automatic discovery is a separate confirmed action explaining that only fresh complete DNS discovery can restore automatic trust. Each success reloads the stored revision and audit state; an old form receives a conflict with Reload current revision, preserving the attempted text separately until the member chooses to discard it. Retry reuses the same idempotency key, never duplicates an operation. Show empty, loading, saving, saved, validation error, pending, verified, rejected with safe reason, revoked, failed-read and retry states. A failed read offers Retry and no editable default pretending to be stored state.

The selector has no option for foreign or unverified claims. Ordinary members receive a clear permission refusal; no cross-tenant detail is returned. At 360 px and desktop widths, both themes show labelled controls, keyboard-reachable confirmations with returned focus, status announcements and no horizontal overflow. No registered private contact or bank data is included.

## Platform review

Add Gateway relay review to the existing Access-protected admin navigation. A paginated pending-revision list opens an immutable detail view showing organisation, verified claim, gateway/provider, exact canonical CIDRs, revision, proposer and time. The reviewer records an independently established official source URL, retrieval time and digest of the reviewed range set. Tenant-provided material is labelled unverified and is never fetched by the server as an instruction.

Approve and Reject submit the exact revision with an idempotency key; rejection requires a bounded safe reason. Approval requires independent authenticated platform authority distinct from the proposing tenant identity, even with multiple memberships. The API revalidates current revision, verified claim and binding. Stale, removed, revoked or changed bindings refuse with Reload current revision, never silently approve the replacement. Success reads back the stored decision and audit entry. Empty queue, loading, failed read, saving, validation error, conflict, decision saved and retry states use existing admin tokens and accessible components. A rejected revision can be corrected only by a fresh member proposal; approval is reversed through the member revocation lifecycle, never by editing the historical decision.
