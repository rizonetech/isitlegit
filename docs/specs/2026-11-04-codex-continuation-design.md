# Codex unattended continuation

The coordinator owns shared lifecycle tooling and D00 from 4 November 2026. All lanes run unattended with no blocking questions. User stops, session ownership, product safety and honest review evidence remain mandatory.

Native hooks own continuation and interruption. State lives outside Git in `~/isitlegit-data/handover/codex-continuation/`, one locked record per lane. Activation explicitly selects a session and canonical worktree. Foreign hook events never claim ownership. Interrupt pauses the owner until an explicit activation. Stop can continue an enabled owner whose final outbox wait is `none`; other waits leave an idle state for later inspection. No model output is treated as a machine instruction.

WORKAROUND: the installed Codex API exposes no native recurring scheduler. A user-systemd timer runs a bounded heartbeat every five minutes through the installed app-server native `thread/read` and `thread/queue/*` APIs over its existing local Unix WebSocket (the installed CLI-generated schema is authoritative). It is a host heartbeat, never a native Codex job. A queue result is only queued, not delivered. The next matching lifecycle event acknowledges it. Active sessions, paused sessions and missing lifecycle evidence never receive a wake. An outstanding wake is not queued repeatedly. A queue warning or failure is recorded for coordinator inspection.

Native hook trust remains an operator-controlled runtime boundary. A file on disk or a unit test cannot prove a trusted hook executed. The coordinator prepares the exact hook sources and records the one-time trust step if the runtime requires it; no trust bypass is added. Installation and session execution are reported separately. The heartbeat never impersonates a Claude cron ID or acquires its campaign guard.

Rollback: pause registered owners, disable the project user timer, remove only the project timer units, then remove the repository hook definitions. Existing training, render processes, other hooks and other projects are untouched. Previous shared-tool ownership was eval's D00 domain; reassignment removes D00 from eval and returns it to the coordinator default. Reversing it is one lane-map change at a safe boundary.

## State and race contract (plan review repairs)

The registry stores a session UUID, canonical worktree, launch claim, monotonically increasing generation, phase (`unverified`, `active`, `idle`, `paused`, `complete`), current turn ID, and pending wake identity. The launcher atomically reserves a worktree before starting Codex; a second launcher refuses even before SessionStart. SessionStart can bind only that launch claim. Direct launches are outside the supported unattended entrypoint and cannot activate over a reserved owner. An abandoned claim is recovered only through an explicit release command after checking its PID and the native thread status; a paused claim is never silently replaced. Existing attended sessions activate explicitly after operator-confirmed exclusive ownership, as main did on 4 November.

The host checks native `thread/read` status immediately before dispatch, never inferring idle from log age. A new user turn marks its exact turn active through UserPromptSubmit, and PreToolUse revalidates ownership and generation. Stop applies only to the current turn. Interrupt writes a pause marker immediately, then advances the generation and invalidates every outstanding wake belonging to that generation. Stale Stop and SessionStart cannot undo a pause. A conversational stop is honored by invoking the pause command before acknowledging it; the launch prompt states this explicitly. User stop actions never require a confirmation question. The pause marker is checked both before and after queue submission, and by UserPromptSubmit and PreToolUse; a revoked wake cannot execute tools.

Each wake has a UUID persisted before submission and carried in the prompt. Native queue add uses it as `clientUserMessageId`; read-back correlates the returned queued submission ID. Pause deletes only this owned queued submission through `thread/queue/delete`, never unrelated user input. Unknown submission outcomes stay pending and reconcile through queue list by that same identity; they are never blindly resubmitted. A matching UserPromptSubmit containing the wake UUID acknowledges the wake. Unrelated user activity marks active but does not acknowledge delivery. A ten-minute unacknowledged wake becomes a visible stalled state for coordinator recovery, not an infinite retry loop. A queued turn already started before pause is denied continuation and tool execution by the generation/marker guard; native interruption is requested only for that identified wake turn when needed.

Wait policy: `none` allows continuation; a timezone-aware `time:` resumes once reached; an exact `stamp DNN TNN §N on main` resumes only against the published main plan's exact stamped row, never a substring or an unpromoted local plan. Coordinator-gate waits are released explicitly by the coordinator after exact-SHA CI verification; operator waits stay parked. Unknown, absent or stale outboxes refuse automatic wake. Completion is an explicit `complete` state and disables all continuation until new activation. Every Stop that would continue checks for actual repository/run-record progress; three unchanged continuations park with a visible stalled reason to avoid a tight usage loop.

Tests cover competing launch reservations, generation/turn mismatches, a pause before queue, during submission and after queue acceptance, interruption versus delayed Stop, queued acceptance followed by process death, unrelated activity versus correlated acknowledgement, active-thread refusal, stalled wake handling, exact stamp matching, uncleared/cleared waits, completion, and a paused owner after daemon or timer restart. Transport tests use a local fake WebSocket server and no model calls. Real runtime acceptance is separate and mandatory: timer installed/enabled, observed tick after restart, trusted Stop and Interrupt execution, and an acknowledged heartbeat resume for each intended real coordinator/lane. If trust or session creation is absent, runtime coverage remains incomplete and the section stays unstamped while other work proceeds. Rollback is verified by disabling the timer and confirming no tick or automatic wake while paused.

Native protocol reference: [Codex App Server](https://learn.chatgpt.com/docs/app-server), plus the installed CLI's generated `ThreadRead`, `ThreadQueueAdd`, `ThreadQueueList`, `ThreadQueueStart` and `ThreadQueueDelete` schemas. Hook behavior: [Codex hooks](https://learn.chatgpt.com/docs/hooks). No daemon restart or shared runtime reconfiguration is required.
