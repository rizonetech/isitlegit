**Comparator: Microsoft 365’s native inbound authentication, including Defender for Office 365.** It evaluates authentication during receipt and records SPF, DKIM, DMARC and composite results. It also supports configured third-party gateway routes through Enhanced Filtering for Connectors. These are documented capabilities; I did not benchmark its latency or interface. 2. **in-scope: excessive damaged-input latency.** The measured folded-header case consumes 4.4 seconds before other checks can progress. There is no measured speed advantage over the comparator. **Target:** process that fixture within 100 ms on the same test runner, demonstrate approximately linear scaling, and complete or yield within the declared one-second budget. This addresses Part 1 item 11.

3. **in-scope: discovery can require user intervention indefinitely.** Native authentication does not depend on this application discovering every organisation domain. Here, unrelated empty or failing domains can permanently prevent authentication evidence for a healthy domain. **Target:** with three due domains and two lookup slots per case, attempt the healthy third domain by the second case, preserving the cap and old rows on failure. This addresses Part 1 item 7.

4. **out-of-scope: weaker coverage of common gateway deployments.** Microsoft documents a configuration for mail passing through another security service before Microsoft 365. The candidate’s MX-only model cannot represent that receiving chain. **Target:** a new verified-chain design covering both gateway-to-Microsoft and gateway-to-Google fixtures, with valid results retained and injected results rejected. Owner: **02-checks**, with **07-app** if configuration controls are needed.
