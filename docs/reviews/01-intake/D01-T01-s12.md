A failure during child admission, raw storage or Workflow creation therefore leaves missing or unstarted children permanently skipped. The retry test covers only replay after successful completion.

2. **P1: Child admission lacks durable, deterministic identity.** [analysis-workflow.ts:702](../../../src/pipeline/analysis-workflow.ts#L702) admits a fresh `ulid()` before recording its manifest row. An interruption between those writes leaves an orphan consuming capacity; concurrent parses can admit separate cases for the same position before one manifest insert wins. This does not implement the correction’s parent-and-position-derived ID or atomic recovery contract.

3. **P1: A child can send an incomplete group before the parent finishes.** [analysis-workflow.ts:1345](../../../src/pipeline/analysis-workflow.ts#L1345) checks only admitted children, treating the caller as terminal without checking the parent. With two originals, a child finishing first sends the parent as “no verdict”; the eventual parent result cannot replace that already-claimed group reply. Children also start while later manifest rows are still being created, so the expected group is not sealed before sending becomes possible.

4. **P1: Concurrent child completion can leave the group without any reply.** The same terminal check reads other children’s persisted statuses, but successful cases become `done` only after their reply step at [analysis-workflow.ts:534](../../../src/pipeline/analysis-workflow.ts#L534). If the parent has finished and two children reach reply together, each can see the other still running and return `waiting`. Both then finish without another aggregation trigger. The shared send key prevents duplicates but does not ensure a sender eventually runs.

5. **P2: Extraction still prioritises type across the forward.** [forward.ts:95](../../../src/intake/forward.ts#L95) uses `chosenOf(found)`, which prefers any RFC822 attachment over earlier `.eml` or `.msg` attachments. An earlier `.eml` followed by RFC822 therefore becomes original two. With six mixed-format attachments, a later RFC822 can also displace an earlier original from the five admitted entries, contrary to the corrected attachment-order requirement.

6. **P2: Admission errors are misreported as cap refusals.** [analysis-workflow.ts:715](../../../src/pipeline/analysis-workflow.ts#L715) records every unsuccessful `admitCase` result as `refused-cap`. That API also returns database and validation failures. A transient database failure can therefore permanently exclude an original and falsely tell the member their daily limit caused it.

7. **P2: The grouped presentation does not meet SPEC N1.** [reply.ts:251](../../../src/mail/reply.ts#L251) provides no failure-specific advice for no-verdict blocks. Its [HTML output](../../../src/mail/reply.ts#L282) also omits the member frame and dispute footer, although the plain-text version includes footer text.
