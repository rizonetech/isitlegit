2. **P2: The named fixture does not exercise compression.** The [fixture builder](../../../scripts/fixtures/msg-builder.ts#L151) creates `rtf-only.msg` using uncompressed MELA. Its successful extraction cannot prove LZFu decompression. Require a genuine compressed fixture with dictionary references and exact expected output, alongside MELA coverage. These are distinct [MS-OXRTFCP formats](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-oxrtfcp/a1f226ed-31e3-4565-9d26-af3c6714c93f).

3. **P2: Plain-text extraction is underspecified and “control words dropped” loses content.** [Line 485](../../../todo/01-intake/TODO-01-email-intake.md#L485) omits signed `\uN`, scoped `\ucN` fallback skipping, escaped braces/backslashes, tabs, destination skipping and font-specific code pages. Require exact-output tests covering these, including multibyte `\'xx` sequences and nested groups. Otherwise Unicode can disappear, fallback characters duplicate, and font-table text enter the body. [Microsoft’s extraction rules](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-oxrtfex/205e1abf-b794-4fd0-b1e4-5210882233ab) distinguish textual controls from formatting controls.

4. **P2: HTML de-encapsulation has no discriminating test.** [Line 485](../../../todo/01-intake/TODO-01-email-intake.md#L485) requires one HTML fixture but does not require interleaved shared text, `htmltag` destinations and `htmlrtf` suppression. Specify those cases and assert exact HTML, including links, entities and escaped characters. A tags-only extractor or plain-text stripper could pass a simple fixture while losing or duplicating evidence. Microsoft’s [encapsulation example](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-oxrtfex/fc107c62-c62f-48d4-b114-d7e3d1c8f54b) exercises that interleaving.

5. **P2: Integration does not specify the extracted-body budget contract.** [Line 486](../../../todo/01-intake/TODO-01-email-intake.md#L486) should explicitly route plain output into `parsed.text` and encapsulated HTML into `parsed.html`, through the [existing byte-budget helpers](../../../src/intake/msg.ts#L234). State the output encoding, enforce the 1 MiB per-part and 2 MiB total limits after extraction, and preserve complete extracted bytes with the correct media type/charset in `truncated`. Encoding conversion can expand bytes even when decompressed RTF fits. Require boundary, multibyte-cut and stored-artifact read-back tests.

6. **P2: Malformed-input outcomes are undefined.** [Lines 484 onward](../../../todo/01-intake/TODO-01-email-intake.md#L484) need explicit `ParseError` outcomes and tests for invalid headers/type, bad compressed CRC, truncated tokens, invalid termination and malformed RTF syntax. Currently the [empty-message guard](../../../src/intake/msg.ts#L228) permits a message with a subject or transport headers, so returning empty text on failure could silently replace today’s explicit refusal. Also test that malformed RTF remains ignored when a native text or HTML body exists.
