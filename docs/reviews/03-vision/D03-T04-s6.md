1. **P1, §6 [line 246](../../../todo/03-vision/TODO-04-glimmer.md#L246), line 250:** Recording a licence does not enforce the required commercial-use acceptance gate. [Tranco’s attribution](https://tranco-list.eu/) includes a CC BY-NC component; the design already makes Tranco conditional on compatible terms. Add verified acceptance or a compatible fallback, refusal tests, and the required licence-register entry. Separately record permission for captured page content: naming the URL list as its `licence` does not establish that permission.

2. **P1, §6 [line 249](../../../todo/03-vision/TODO-04-glimmer.md#L249):** Password-only detection contradicts the existing [shared prompt](../../../src/vision/page-screen.ts#L48), which defines login forms as asking for a username, email or password. Identifier-first pages therefore receive incorrect training labels. Align DOM detection with that contract, including visible forms inside frames, and test username-only, email-only, password, hidden-field and payment-frame cases. §9 fills missing flags; it does not repair these already populated false values.

3. **P2, §6 [lines 248 and 250](../../../todo/03-vision/TODO-04-glimmer.md#L248):** The plan lacks a usable-page acceptance gate before assigning benign ground truth. Popularity is not page verification, and a successful render can capture a loading shell, bot challenge, consent wall or unrelated redirected page. Tranco itself distinguishes popularity ranking from malicious-site filtering. Specify permitted final destinations, bounded readiness checks and exclusion or review of unusable or unverified captures. Test these outcomes, including HTTP errors and cross-site redirects; the existing two-success/one-failure fixture does not prove them.

4. **P2, §6 [line 248](../../../todo/03-vision/TODO-04-glimmer.md#L248), checkpoint line 254:** The renderer’s isolation promises are unproven. A normal fixture and timeout test can pass with shared contexts, enabled downloads, pop-ups or service workers. Add behavioural tests for the named restrictions, context cleanup after failures, and the complete 20-second operation limit. Because this browser runs locally against external pages, also define and test the network boundary preventing redirects or requests into local/private services.

5. **P2, §6 [line 250](../../../todo/03-vision/TODO-04-glimmer.md#L250):** Resume is specified only for a clean rerun. Interruption after `putPage` but before progress append leaves an unrecorded success; rendering that live URL again can produce different bytes and another page ID. A truncated journal or transient failure also has no recovery rule. Add recoverable URL-to-page identity, journal repair, explicit retryable versus completed outcomes, and tests interrupting between storage and progress persistence, including write failure.

6. **P2, §6 [line 251](../../../todo/03-vision/TODO-04-glimmer.md#L251):** The stated completion evidence cannot produce the required measurement. Existing [`counts()`](../../../scripts/glimmer/store.ts#L308) reports source and lure-label totals, with no South African or origin breakdown. Add a persisted-manifest check scoped to `origin: benign`, verifying at least 3,000 pages and 300 South African pages. Test that unrelated benign-labelled imports cannot satisfy these totals.

7. **P2, §6 [line 247](../../../todo/03-vision/TODO-04-glimmer.md#L247), line 251:** Coverage is tested only in the input URL list. The run can meet aggregate totals while login, checkout or social captures all fail, leaving the promised negative examples absent. Persist each input’s kind and brand with its capture outcome, define successful-capture minimums per required kind, and replenish rejected URLs until those minimums pass. Read-back tests must verify the screenshot/text pairing, brand, regional marker and label provenance.
