### integration: needs-attention

2. **P2, [confirm.tsx:348](../../../src/auth/confirm.tsx#L348): A failed attempt refund permanently locks a correct code while promising a retry.** Enter two wrong codes, exhaust the IP’s verification allowance, then submit the correct code while D1 fails the `giveBack` operation. The in-memory fault probe reproduced this state. Refund recovery must remain durable, or the response must provide an accurate recovery path.

### source-defect: needs-attention

3. **P2, [signin-code.ts:116](../../../src/auth/signin-code.ts#L116): Cookie scope breaks preserved-code behavior through the public Better Auth endpoint.** `Path=/signin` excludes `/api/auth/sign-in/magic-link`, so a browser calling that supported endpoint never returns its existing handle. [auth.ts:72](../../../src/auth/auth.ts#L72) consequently replaces it on every request, including refused sends. Reproduce by requesting five links for one address through that endpoint, then requesting a sixth within ten minutes: no replacement email arrives, but the handle changes and the fifth email’s code stops working. A cookie-jar probe confirmed the missing header. This follows [RFC 6265’s path-matching rules](https://www.rfc-editor.org/rfc/rfc6265.html#section-5.1.4); the test helper’s jar ignores cookie paths.

### plan-delivery: needs-attention
