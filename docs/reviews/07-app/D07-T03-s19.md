**Part 2: excellence**

Comparator: **Microsoft Defender for Office 365’s Email entity page**, named among the manifesto’s benchmarks. Microsoft documents an entire plain-text header view, a Copy message header action and access to its header analyser. This is documented behaviour, not a hands-on timing comparison. [Microsoft documentation](https://learn.microsoft.com/en-us/defender-office-365/mdo-email-entity-page#analysis-view)

1. **in-scope, G4, speed:** Every preview request reads the complete raw email into memory before reading the summary it actually displays. Switching tabs repeats that work. A supported 25 MiB email with attachments therefore burdens even a small header lookup. Evidence: [artefacts.tsx:252](../../../src/web/pages/artefacts.tsx#L252), [store.ts:269](../../../src/intake/store.ts#L269). **Target:** zero raw-body bytes read for preview requests, while retaining ownership and existence checks; benchmark small and maximum-size originals with identical displayed text. No measured latency advantage over Defender can currently be claimed.

2. **in-scope, G5, error recovery:** A request that stalls without rejecting leaves “Loading.” indefinitely. Close permits cancellation, but retry appears only after failure. Evidence: [app.ts:1162](../../../src/web/client/app.ts#L1162). **Target:** a bounded deadline, for example 15 seconds, followed by the existing retry state; test a response whose headers or body never finish. This is a concrete recovery weakness, not a claim that Defender has a verified timeout.

3. **out-of-scope, G6, steps and accessibility:** Copying headers requires manual selection and copy rather than Defender’s single Copy message header action. This is particularly cumbersome in a long, scrolling region on a phone. The dialog currently offers only download in its footer: [app.ts:1065](../../../src/web/client/app.ts#L1065). **Target:** one keyboard-operable copy action after opening the headers, with announced success and a selection fallback on clipboard refusal. A new **D07 app** section and approved surface change should own this.

4. **out-of-scope, G7, completeness of inspection:** Defender documents the entire header; this preview cuts headers at the same limit as the body and sends readers to a download for the remainder. A long received chain or large authentication fields can therefore prevent completing the investigation in place. Evidence: [artefacts.tsx:190](../../../src/web/pages/artefacts.tsx#L190). **Target:** access every stored header without downloading, using bounded progressive loading. This requires a new **D07 app** section and design decision; retain the approved initial preview limit.

The one-action opening path does not show a demonstrated step-count disadvantage. I found no supported comparative claim about Defender’s contrast, reduced motion or screen-reader quality, so I have not invented one.
