This comparison uses documented behaviour, not a timed benchmark. Sources: [browsing](https://storybook.js.org/docs/get-started/browse-stories), [viewport](https://storybook.js.org/docs/essentials/viewport), [theme controls](https://storybook.js.org/docs/essentials/toolbars-and-globals), [accessibility results](https://storybook.js.org/docs/writing-tests/accessibility-testing).

1. **in-scope, E1: Finding a specimen takes unnecessary navigation.** The gallery is a sequential list of 68 states followed by 16 frames, without an index or search. Storybook offers a named state selector. **Target:** reach any known state/frame in one index activation, with keyboard access and a shareable anchor. Evidence: [gallery.tsx:356](../../../src/web/dev/gallery.tsx#L356).
2. **in-scope, E2: Unneeded preview work starts immediately.** All 16 frame documents load eagerly, including their scripts, before the developer reaches them. 3. **out-of-scope, E3: Theme and viewport inspection requires external tools.** The test harness selects both themes and widths, but the gallery has no equivalent developer controls. Storybook supplies viewport presets and supports theme toolbar controls. **Target:** select either tested width and either theme within two actions, applying the choice consistently to previews. A new D07 gallery-tooling section should design this surface without changing the product’s OS-theme default. Evidence: [gallery.tsx:356](../../../src/web/dev/gallery.tsx#L356), [a11y.test.tsx:44](../../../test/node/a11y.test.tsx#L44).

Storybook reports violations and unresolved checks alongside the selected state. **Target:** inspect a finding and highlight its element within one activation, with rule guidance and no terminal switch.
