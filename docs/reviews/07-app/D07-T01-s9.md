Part 1: completeness.

1. **present:** Fingerprinted, pinned and licensed scripts. Both assets are exported, retained during pruning and loaded by default. Evidence: [hash-asset.ts:114](../../../scripts/hash-asset.ts#L114), [Document.tsx:34](../../../src/web/components/Document.tsx#L34), `NOTICE.md`; regression coverage in `assets.test.ts:56`, `hash-asset.test.ts:66` and `document.test.tsx:61`.

Evidence: [app-script.test.tsx:109](../../../test/node/app-script.test.tsx#L109). Report polling, filter controls and their loading/error states already belong to D07 T03 §4 and D07 T04 §1, not this section.

3. **present:** Copy control and automation name. The native button is named **“Copy the check address”**, copies the displayed address, and is reachable through **“Menu”** on phones. Evidence: [AppShell.tsx:248](../../../src/web/components/AppShell.tsx#L248). The browser tests locate it by role and accessible name.

4. **missing-out-of-scope:** A visible label on hover and keyboard focus. The copy icon has an accessible name but no tooltip or visible command label; a sighted user must recognise the icon. [Button.tsx:77](../../../src/web/components/Button.tsx#L77) renders the name only as `aria-label`. Owner: **D07**, a new shared-control section with a P1/AppNav design amendment.

5. **present:** Keyboard activation and navigation. Enter and Space invoke copying; existing shell tests cover Tab order, focus contrast and phone Menu dismissal. Evidence: [app-script.test.tsx:131](../../../test/node/app-script.test.tsx#L131), [shell-keyboard.test.tsx:80](../../../test/node/shell-keyboard.test.tsx#L80). This single native-button command needs no separate shortcut or command palette.

6. **present:** Visible success, expiry and refusal states. Success appears after the clipboard promise resolves and clears after four seconds. Permission denial or unavailable clipboard support produces persistent instructions and selects the address for manual copying. Evidence: [app.ts:54](../../../src/web/client/app.ts#L54); tests at `app-script.test.tsx:119` and `:142`. The address is a code-owned constant, not hostile mail content.

7. **missing-in-scope:** Reliable repeated announcements and a regression check that establishes them. With the Clipboard API absent, a second press clears and restores the identical error synchronously at [app.ts:58](../../../src/web/client/app.ts#L58). The probe confirmed both mutations occur before the handler returns. The tests check attributes, final text and selection, so they cannot detect a missing repeat announcement. This leaves the contract’s “announced afresh” promise unproven. Establish a separately observable live-region update and verify repeated refusal and success announcements with assistive technology. W3C’s [live-region example](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA19) explicitly separates clearing from reinsertion.

8. **present:** Theme, phone and feedback-contrast coverage. Tests exercise successful copying at 1280 and 360 pixels in both themes and require feedback contrast of at least 4.5:1. Evidence: [app-script.test.tsx:117](../../../test/node/app-script.test.tsx#L117). Copy feedback introduces no animation requiring a reduced-motion alternative.

9. **present:** Asset persistence, replacement and recovery. Writes use temporary files followed by rename; inputs are read and the app compiled before publication; the manifest is replaced before old assets are pruned. Evidence: [hash-asset.ts:21](../../../scripts/hash-asset.ts#L21) and `:114`. Tests cover rejected compilation, changed fingerprints, interrupted-build debris and failed rename at `hash-asset.test.ts:89`, `:66` and `:192`. Serving tests check JavaScript types and immutable caching at `serve.test.ts:71`.

10. **present:** Proportionate state ownership. Copying creates no application record or saved preference requiring read-back, cancellation or undo. The operating system owns clipboard replacement. The section needs no file dialogs, disk settings or application-level clipboard history.

Part 2: excellence.

The strongest comparable implementation alternative is **GitHub’s Primer copy pattern**: a directly available, single-click control with a descriptive label, tooltip, visible confirmation, live announcement and manual recovery. This comparison uses its [published behaviour](https://primer.style/product/scenario-patterns/copy/), not a measured GitHub session.

1. **out-of-scope:** The command lacks Primer’s visible label for sighted keyboard and pointer users. **Target:** show “Copy the check address” on focus and hover, with accessible dismissal and readable contrast. Preserve the decided visible status line and four-second success duration. This requires the D07 shared-control/design amendment identified in Part 1. Primer documents this purpose for [icon-button tooltips](https://primer.style/product/components/tooltip/accessibility/).

2. **out-of-scope:** Phone copying takes **two activations**, Menu then Copy, versus the alternative’s directly available **one activation**. The extra step is explicit in [app-script.test.tsx:71](../../../test/node/app-script.test.tsx#L71). **Target:** one activation from the normal phone page to copy the address. Owner: **D07**, a new section following an approved phone-shell design change; the current placement follows the existing SPEC.

3. **in-scope:** Accessible repeat feedback does not yet meet a demonstrated dependable-copy standard. **Target:** each deliberate press announces its outcome once, including two consecutive refusals and recovery from refusal to success, without moving focus; preserve persistent refusal instructions. Add a regression check and recorded assistive-technology verification for the Part 1 gap.

There is no measured basis here to claim a speed advantage or disadvantage against Primer. Large-file processing is not performed by this feature.

2. **missing-out-of-scope / out-of-scope:** Add a visible focus/hover label for the copy icon through a new D07 shared-control section and approved design amendment.
3. **out-of-scope:** Reduce phone copying from two activations to one through a new D07 section and approved phone-shell design change.
