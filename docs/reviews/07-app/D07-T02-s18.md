Part 2: excellence

Competitor: **Google Account’s passkey sign-in**. The candidate does not establish superiority over it.

1. **[out-of-scope, G1] Less direct discovery for habitual passkey users.** Google supports passkey suggestions in the username field and a passkey-first preference. Here, members must identify and activate the secondary passkey button each time. This is an intentional tradeoff explicitly settled by [the operator’s decision](../../../design/SPEC.md#L523), not an implementation omission. Google’s documented flow still involves interaction, so a universal extra-click claim would be unjustified. [Google sign-in guidance](https://support.google.com/accounts/answer/13548313?hl=en)
2. **[out-of-scope, G2] Weaker cross-device guidance.** Google explains using a phone’s passkey, scanning the QR code and enabling Bluetooth. The candidate’s “No passkey found on this device?” panel instead steers users toward email, potentially causing an unnecessary inbox detour. §19 owns this improvement. [Current panel](../../../src/web/pages/signin.tsx#L146), [Google cross-device instructions](https://support.google.com/accounts/answer/13548313?hl=en)
