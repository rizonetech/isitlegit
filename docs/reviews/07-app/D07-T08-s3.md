**Part 2: excellence**

**Comparator: Google Account**, a strong account-security alternative for the Gmail users named in the manifesto. Its documented device page exposes individual sessions, recent signed-out devices, activity times and location context, and lets users select a device and sign it out. Its name-change journey is Personal info → Name → Edit → Save. These are documented behaviours, not a live performance benchmark. [Device management](https://support.google.com/accounts/answer/3067630?hl=en), [name editing](https://support.google.com/accounts/answer/27442?hl=en).

1. **in-scope:** Session recency is less trustworthy than Google’s documented last-communication time. Target: activity displayed within five minutes of an authenticated request, including activity before session renewal; test two simultaneously active sessions. This is completeness item 10.

2. **in-scope:** Members without an organisation have no discoverable path to their settings. Target: Account reachable in one action from the post-sign-in refusal page, with no organisation creation required. This is completeness item 2.

3. **out-of-scope:** The security response stops at inspection. Google provides device selection followed by Sign out; this candidate cannot revoke another session at any click count. Target: finish §13 with row action plus confirmation, and verify the revoked session immediately loses access. Preserve the already-decided confirmation requirement.

4. **out-of-scope:** Session recognition lacks Google’s location context and recent signed-out history. Two “Chrome on Windows” entries can remain difficult to distinguish. Target: a new **D07 account-security section**, with an approved design and privacy policy, providing bounded recent history and clearly qualified location context where available.

5. **in-scope:** Recovery and feedback do not meet the intended polished experience: a failed save requires retyping, and a successful save lacks dependable announcement. Target: zero retyping after server failure, stored and attempted values clearly distinguished, and the result reached and announced after one Save. These are completeness items 6 and 8. Google’s documentation does not establish its failure-draft behaviour, so this is a delivery-quality finding, not a claimed measured Google advantage.

No measured latency comparison supports a speed finding. The candidate’s direct name-edit form already uses fewer navigation steps than Google’s documented journey; adding dialogs would weaken it.
