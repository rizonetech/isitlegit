1. **P1: Feedback notices can be permanently lost.** [Line 276](../../../todo/07-app/TODO-03-report-page.md#L276) requires only the first feedback to trigger mail. If feedback commits and the Worker stops before sending, or `sendMail` returns `failed`, nothing schedules another attempt. The existing reconciler settles uncertain sends but never resends them. Add durable pending-notice state and a retry owner, using one stable case-level key. Test interruption after persistence, failed-send recovery, concurrent submissions and uncertain-send handling.

2. **P2: Saved feedback has no read-back or usable correction flow.** [Line 274](../../../todo/07-app/TODO-03-report-page.md#L274) replaces the control with thanks, although the contract promises that members can replace their choice and note. Add a saved-feedback state, an edit action and prefilled values on reopening or reloading. Test correction through the browser and subsequent read-back, with another member’s feedback remaining separate. Two direct POSTs do not prove this user journey.

3. **P2: Field validation can silently discard the note.** [Lines 273 and 274](../../../todo/07-app/TODO-03-report-page.md#L273) test the database constraint and oversized bodies, but not invalid fields through the endpoint. `readSmallForm` silently omits fields exceeding their configured limit. A 1001-character note within the body limit can therefore become an accepted null note, bypassing the table constraint. Require explicit field validation and accessible errors preserving the input; test missing or invalid kinds and overlong notes through POST, with no write or notification.

4. **P2: Feedback eligibility is undefined when there is no verdict.** [Line 274](../../../todo/07-app/TODO-03-report-page.md#L274) adds the control for members without distinguishing running, failed, complete and partial reports. Running and failed reports genuinely have no verdict to dispute. Specify eligibility in both rendering and POST validation, explain any disabled state, and ensure feedback becomes available when a running report finishes. Test complete and partial verdicts, absent verdicts and the live transition.

5. **P2: The new write endpoint’s tenant boundary is unproven.** [Line 274](../../../todo/07-app/TODO-03-report-page.md#L274) tests a link holder but not a signed-in member of another organisation. Require current membership in the case’s organisation, derive `user_id` from the session and preserve access for membership in a non-active organisation, matching the report route. Add tests for foreign and removed members, spoofed user identity and membership-query failure, asserting no feedback write or notice.

6. **P2: The attribution test does not prove that the verdict cited the provider.** [Line 275](../../../todo/07-app/TODO-03-report-page.md#L275) passes even if implementation records every reputation provider on the case. Add a fixture containing both cited and uncited listings, multiple citations and repeated providers; assert the exact deduplicated provider set through the POST and database read-back. Also cover legacy string reasons without citations. Otherwise the promised provider statistics can attribute disputes to unused evidence.

7. **P2: The notice requirement contradicts N9 and its test checks only quantity.** [Line 276](../../../todo/07-app/TODO-03-report-page.md#L276) specifies a case link, while N9 requires “Open the feedback queue.” An ordinary report URL also requires organisation membership or a signed link; operator status alone grants neither. Specify and test the notice’s operator-accessible destination, summary and exclusion of the note. Keep the queue implementation owned by D07 T08 §5, but explicitly resolve the interim action and N9 handoff.
