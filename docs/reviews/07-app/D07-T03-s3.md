1. **P1: Check totals have no reliable source, and the safe-state panel is unowned.** [Section line 166](../../../todo/07-app/TODO-03-report-page.md#L166) requires counting checks run from evidence items. Successful checks can return `[]`, multiple findings can share one check, and one `not_checked` item can represent several checks. The pipeline persists findings, not individual execution outcomes. M3 also requires “Checks that found nothing”, which neither this section nor its named deferrals builds. Add a prerequisite owned by the checks lane that persists per-case check outcomes, then read them for both surfaces. Test successful checks with zero findings, multiple findings, grouped skips and historical cases independently of today’s registry.

2. **P1: The inline-image rule admits active SVG attachments.** [Section line 167](../../../todo/07-app/TODO-03-report-page.md#L167) permits images inline with their own media type. Intake preserves the attachment’s declared type, and [`attachment.html` explicitly produces evidence for SVG files](../../../src/checks/html-attachment.ts#L244). Thus an accepted hostile SVG qualifies for inline delivery from the application’s origin. Specify verified passive image formats for inline responses; serve SVG and other active or mismatched content as inert downloads. Extend the checkpoint beyond HTML with SVG and falsely declared image fixtures.

3. **P1: Artefact access can pass its tests without working for an authorised reader.** [Section line 167](../../../todo/07-app/TODO-03-report-page.md#L167) tests refusals and HTML typing, but never follows a rendered card’s actual URL successfully. Stored keys contain slashes, and `verifyReportLink` accepts only `/r/<caseId>`, so key encoding, signature verification for `/a/` and propagation of signed-link parameters need an explicit contract. Add route tests that persist an artefact, open the report as both a member and an anonymous signed-link holder, follow its generated URL, and verify the exact bytes and headers. Include expired and tampered signatures and a member opening with an expired link.

4. **P2: The phone’s “more findings” control is missing.** [Section lines 166 and 170](../../../todo/07-app/TODO-03-report-page.md#L166) require cards and responsive checks but omit the disclosure drawn in [`Report-Mobile`](../../../design/mockups/source/Report-Mobile.dc.html#L75). No named section owns it. Specify which cards remain visible, the remaining count, expansion and collapse, and automatic disclosure when a reason targets a hidden card. Test keyboard activation and focus on the revealed target, including direct fragment navigation.

5. **P2: Renderer coverage does not prove the evidence is displayed correctly.** [Section line 165](../../../todo/07-app/TODO-03-report-page.md#L165) can pass with family renderers that output only the common summary. One fixture per registered check also misses real variants: `domain.age` has both dates and unchecked-domain records; `content.hidden_text` has quotes, overflow counts and incomplete-scan records. `not_checked` is deliberately absent from `checks.names()`. Require field assertions for each existing variant, both runner failure shapes, hostile quoted text, and persisted evidence read through the report route. Removing a quote, date, comparison or missing-check explanation must fail a test.

6. **P2: Artefact recovery is only a label, and missing does not establish expiry.** [Section line 169](../../../todo/07-app/TODO-03-report-page.md#L169) asks for a “retryable” rendering without defining or exercising a retry action. It also equates a missing object with 30-day deletion, although [`readArtefact`](../../../src/intake/store.ts#L240) distinguishes an absent row, an absent object, database failure and storage failure without establishing why an object disappeared. Define these states, reserve the retention explanation for supported cases, and add a working retry that preserves access credentials. Test failure followed by successful recovery while the finding and verdict remain readable.
