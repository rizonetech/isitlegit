1. **P1, [§1 lines 55–56](../../../todo/06-invoice/TODO-02-payment-documents.md#L55): Object scanning and marker counting do not establish the active document or its revisions.** “Last definition of a number wins” ignores generations, deleted objects and cross-reference precedence; PDF-looking bytes inside streams can be mistaken for objects or revisions. Require resolution through validated xref tables/streams, `/Prev` and `/XRefStm`, with structural linearization handling. Test deleted/replaced objects, hybrid references, embedded markers and an incrementally updated linearized file. Matching two Info dictionaries does not prove this. [Cross-reference rules](https://qpdf.readthedocs.io/en/stable/object-streams.html).

2. **P1, [§1 lines 55 and 60](../../../todo/06-invoice/TODO-02-payment-documents.md#L55): Refusal and partial-analysis outcomes are underspecified.** Only oversized and wholly unreadable files have explicit acceptance tests. Add typed outcomes and tests for encryption, unsupported filter chains or predictors, corrupt Flate streams, truncated objects and invalid references. Define which findings survive partial reading and which checks remain unavailable. A readable metadata finding beside an unreadable page must survive with a partial reason; missing content must not become a clean result. Export that coverage contract for §3.

3. **P1, [§1 lines 45 and 55](../../../todo/06-invoice/TODO-02-payment-documents.md#L45): The bounded-work claim is unproven.** File/object/token caps alone do not bound reference cycles, recursive page/Form traversal, repeated expansion or image-to-text comparisons. Require traversal-depth and total-work budgets, cycle detection, aggregate streaming decompression limits enforced before buffering, and bounded overlap analysis. Test hostile inputs below the file-size limit and measure worst-case CPU/memory in workerd. The repository explicitly says synchronous checks cannot be interrupted; [Workflows also impose CPU limits](https://developers.cloudflare.com/workflows/reference/limits/).

4. **P1, [§1 lines 57–59](../../../todo/06-invoice/TODO-02-payment-documents.md#L57): The text-and-position reader needed by three findings is not specified or tested.** Reading dictionaries and listing resources does not identify the issuer, payment date, amount/account lines or text bounds. Add content interpretation covering text-showing operators, font encodings/ToUnicode, text positioning, content arrays and Form XObjects, with explicit unsupported outcomes. Test encoded and positioned text through the actual analyser. Image-only PDFs and unmappable text need unavailable coverage, not an empty result implying those checks succeeded. [PDF text mapping](https://opensource.adobe.com/dc-acrobat-sdk-docs/standards/pdfstandards/pdf/PDF32000_2008.pdf).

5. **P1, [§1 lines 56–57 and 60](../../../todo/06-invoice/TODO-02-payment-documents.md#L56): Normal document history can become high-severity tampering evidence.** A genuine POP downloaded after the payment date satisfies the date rule; a subsequent signature or metadata save can supply the second kind and trigger automatic escalation. Require meaningful corroboration rather than counting correlated kinds. Add genuine later-download, metadata-only update and signing fixtures. Define timezone/date-only comparisons, missing or conflicting metadata, and creation-date checks against invoice and bank-letter dates, which the current payment-date-only rule omits.

6. **P2, [§1 line 45, item 4, and line 57](../../../todo/06-invoice/TODO-02-payment-documents.md#L45): A bank mention does not establish bank authorship.** A supplier invoice produced in Word normally names the supplier’s bank. The proposed classifier can therefore defeat the promised supplier-invoice negative control. Require issuer-context attribution, distinguish beneficiary banking details and generic payment-confirmation titles, and return unknown when authorship cannot be established. Include those cases in the producer tests.

7. **P2, [§1 line 58](../../../todo/06-invoice/TODO-02-payment-documents.md#L58): Font subsetting and legitimate numeric typography are treated as substitution.** Different subset tags can legitimately identify subsets of the same font; a separate numeric font can legitimately occur only in amount/account fields. Require evidence beyond either condition alone, and test repeated subsets, merged pages and intentional numeric fonts alongside actual substitutions. The bold-total control does not cover these false positives. [ISO 32000-1, §9.6.4](https://opensource.adobe.com/dc-acrobat-sdk-docs/standards/pdfstandards/pdf/PDF32000_2008.pdf).

8. **P2, [§1 line 59](../../../todo/06-invoice/TODO-02-payment-documents.md#L59): Geometric overlap does not establish pasted-over text.** Genuine scanned PDFs can contain an image and invisible OCR text in the same location. Background images, clipping and transparency also change whether text is obscured. Specify paint order, visible text, graphics-state handling and supported masking behaviour, marking unsupported cases partial. Add OCR, background/watermark and nested-Form controls; a logo placed clear of text proves none of these.

9. **P2, [§1 line 60](../../../todo/06-invoice/TODO-02-payment-documents.md#L60): Evidence acceptance does not prove usable explanations or safe output bounds.** `evidenceIn` permits an empty detail object, so generic summaries can pass without showing what changed or where. Require finding-specific observations, page/object or field locations, compared values and cautious plain-language explanations. Test long filenames, hostile metadata/font names and many findings against the existing summary, detail and item limits. Otherwise valid detections can be rejected wholesale by the runner when §3 integrates them.

10. **P2, [§1 lines 45, 55 and 63](../../../todo/06-invoice/TODO-02-payment-documents.md#L63): The proof can validate only the bespoke writer’s narrow PDF dialect.** The reader checkpoint checks Info dictionaries, while the final checkpoint requires only revision-count sensitivity.
