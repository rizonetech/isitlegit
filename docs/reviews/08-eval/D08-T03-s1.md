Require the existing shared-lock protocol around ledger reads and updates, with a contention test proving another caller’s entries survive.

4. **P2, §1 lines 63 and 65: resume only handles successfully saved answers.** A process can receive a paid answer and stop before replacing `results.json`; the specified rerun then sends that image again. Refusals, invalid structured answers, timeouts and incomplete responses also have no persisted outcome or scoring policy. Add a pending record before sending, durable terminal states and recovery that preserves uncertain spend without automatically resending an ambiguous attempt, following the teacher runner’s existing pattern. Test interruption after send and before result replacement. Define how an incomplete experiment is recorded without claiming 20 answered images.

Require readable invoice content, explicit differing source/replacement numbers, pinned fonts, verification of each intended edit mechanism, and matched whole-page encoding histories. Include benign typography/compression variation or explicitly limit the conclusion to pristine generated invoices. Tests must reject blank pages, obscured digits and edits that introduce only an unrelated rectangle.

Add rejection tests for changed images/settings, duplicate or missing results and malformed stored answers; the fixed-answer arithmetic test does not exercise these failures.
