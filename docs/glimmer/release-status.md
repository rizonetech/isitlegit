## Output contract and hosting

Version 1.1 uses the brand-free answer contract in [`page-screen.ts`](../../src/vision/page-screen.ts): login-form presence, payment-form presence, lure classification, lure type and confidence. Brand metadata is not a required model answer. The runtime must choose the matching prompt and strict response schema; changing a model name alone is insufficient. Missing or invalid model output remains an error, never a fabricated successful classification.

Training and inference run on Fireworks AI. The Cloudflare Worker orchestrates investigations and calls the dedicated inference endpoint through AI Gateway. The model weights do not execute inside the Worker. This release does not claim a public Hugging Face weight upload or model repository.

## Preregistered diagnostic

The post-training synthetic diagnostic v2 contains 40 original inert pages: 20 labelled lures and 20 benign pages, ten layout families and one shared generator family. Both model versions receive the same brand-free prompt and the same screenshots, visible text and order. V1 was preserved; v2 changes the request contract before measurement. V2 manifest SHA-256: `5722055c70fb41c9bb43db9d04f10115b85f79857cebd9b2d3797e609c19ad67`.

This is a small synthetic diagnostic, not an independent held-out population or acceptance of D03 T04 §50. It does not establish general phishing accuracy, superiority over Muse Wonder, or compliance with the project's false-positive target. The existing 17 provenance issues and 257 baseline-training overlaps remain unresolved; complete source/template lineage and prior-exposure exclusion against both training exports have not been proved. Its 40 pages must not be presented as 40 independent source groups.

The completed paired v2 run returned 40 valid answers and zero errors for each model. Both labelled every page as a lure: true positives 20, false positives 20, true negatives 0 and false negatives 0. Each therefore scored 20/40 accuracy (50%), 20/20 lure recall (100%) and 20/20 false alarms (100%) against the frozen synthetic labels. The diagnostic does not show an improvement. Baseline 1.0 used the same brand-free prompt as 1.1, rather than its native brand-bearing contract.

Candidate 1.1 median latency was 2,067 ms and p95 4,388 ms; baseline median was 2,088 ms and p95 4,224 ms. Lure-type accuracy was 50% for the candidate and 85% for the baseline. These are timings and results for this diagnostic, not production service guarantees. Earlier attempts returned provider HTTP 404 errors before valid inference; those remain operational errors, not classification results. All diagnostic activity through the paired run had a conservative elapsed-capacity estimate of US$4.14 at US$12/hour, not a settled invoice or per-request token cost.

A further six-call 1.1 check obtained six valid responses identifying the exact candidate model, with zero errors. It tested one lure and two benign cases separately as text-only and image-only inputs. Both benign cases remained false positives in both modalities. That rules out a failure confined exclusively to screenshot processing or combined-input construction for those cases; it does not establish the training cause. Prompt or synthetic-test-data mismatch remains a hypothesis, not an explanation proved by these calls. The six calls do not replace or alter the frozen 40-page results.

## Fresh post-rollout scenarios

A fresh post-rollout six-scenario run produced four valid answers and two provider scaling errors (HTTP 503 on the benign login and benign invoice). Among valid answers: TP3, FP1, TN0 and FN0, giving 3/4 accuracy and 3/3 lure recall. The false-alarm denominator is only the one valid benign answer: 1/1, not 1/3. The two failed benign requests remain errors, not negative classifications. The ordinary no-form business page was falsely called impersonation with confidence 0.7. The payment lure was detected as a lure but incorrectly reported a login form rather than a payment form. Four raw answers matched their parsed answers, so the scorer did not flip those classifications. Accounting closure was still pending when this result was recorded.

The cause remains unresolved between generalization on these synthetic fixtures and serving/template/adapter behavior. Training metadata contains 43,425 `none` labels among 72,375 examples (60%); a bounded inspection of the first 512 actual targets found 315 negatives, all matching the canonical prompt and strict boolean/type contract. This contradicts an all-positive training explanation, but is not a whole-corpus audit or proof of numerical adapter application. No additional calls or post-hoc relabelling were used to improve the result.

A separate four-page ordinary benign diagnostic returned three valid answers and one HTTP 503 scaling error. All three valid answers (business, catalogue and documentation) were false positives, giving 3/3 false alarms among valid benign answers; the article was an error, not a true negative. The three raw outputs matched parsed answers. The pages used distinct no-form layouts without warning, payment or phishing terminology, so false positives were not limited to the earlier login/invoice scenarios. The underlying generalization versus serving-template/adapter cause remains unresolved. This is not independent qualification or an improvement.

A subsequent controlled matrix made exactly 12 requests, all valid with no errors, using the same three synthetic pages (two benign and one credential lure) across the untuned base and 1.1 candidate under two prompts. For each prompt, the base returned TP1, TN2, FP0 and FN0; the candidate returned TP1, FP2, TN0 and FN0. All raw answers matched parsed answers. The prompt variant did not improve candidate classifications. This localizes the observed difference to the candidate path, but does not distinguish learned generalization failure from a training or adapter-serving defect. These are three reused pages, not 12 independent examples, and the result is neither a general accuracy claim nor a solved-cause claim.

The matrix comparison above concerns the `lure` boolean only. The base returned `lure: false` with `confidence: 0.95` on benign pages, whereas the production/training contract defines confidence as P(lure). Thus those correct booleans do not make the base a drop-in production replacement. No confidence inversion, normalization or production switch is claimed. Provider usage reported zero reasoning tokens for the candidate and 149 to 329 for the base; that difference is an investigative clue, not a proven cause.

A separate visible-feature experiment used six reused synthetic pages and the same frozen four-field ground truth for all three arms. Spark and the untuned base each returned six valid, exact answers (24/24 fields). Loupe 1.1 returned five strict-schema errors, including truncated outputs, and one article request was refused by D1 admission before any model POST; it therefore supplied zero valid feature answers. Missing or invalid outputs were not scored as valid fields. Spark's measured total was US$0.027814; Fireworks per-request costs were unknown, not zero, with GPU accounting retained by the warm-lease owner. Timings included admission. These related fixtures are not independent held-out evidence. The proposed feature-extraction role is not validated for 1.1 and was not deployed by this experiment; no superiority, successful repair or production switch is claimed.

A subsequent candidate-only run changed decoding to provider-enforced `json_schema` while retaining the original six pages, prompt and frozen labels. All six HTTP responses passed the strict four-field schema without answer rewriting, but none of the six records was fully correct. Field matches totalled 14/24: login-form presence 6/6, payment-form presence 5/6, organisation text 0/6 and button text 3/6. The constraint resolved output format, not factual accuracy. The earlier Spark and base 24/24 results used unconstrained decoding, so this is not an equal-settings speed comparison. Earlier failed responses remain preserved; unknown GPU cost is not zero. The 1.1 feature role remains experimental, with no production-role change authorized by these results.
